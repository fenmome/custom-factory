## 一、系统架构

### 1.1 模块划分

```
CustomFactory（模块化单体）
├── Title Factory          # 标题工厂（离线预生成 84,658 个标题）
├── Image Factory          # 图片工厂（UV DTF 8 槽位提示词）
├── Shared Production Core # 共享生产核心
│   ├── Batch Service      # 批次创建与 SKU 分配
│   ├── Image Service      # 图片任务管理
│   ├── QA Service         # 图片质检（技术/语义/人工/OCR）
│   ├── Production Guard   # 生产保护
│   └── READY Service      # 内容生产完成
├── Storage                # 字节存储抽象
├── Providers              # 图片生成提供者
├── Web (DEV UI)          # 本地开发界面
└── Dianxiaomi             # TEMU/店小秘模板
```

### 1.2 数据模型（17 核心实体 + 2 运行时表）

```
Workspace ──┬── User（通过 WorkspaceMembership）
            ├── ProductTypeSkuConfig（SKU 配置）
            ├── Batch
            │   └── Product（SKU）
            │       └── ProductRevision
            │           ├── ListingConcept（冻结概念）
            │           ├── ImageJob（8 个图片任务）
            │           │   └── ImageAttempt（生成尝试）
            │           │       └── ImageAsset（正式图片资产）
            │           │           └── ImageQA（质检记录）
            │           ├── ProductData（属性数据）
            │           └── RevisionQA（修订质检）
            ├── TitleReservation / TitleUsage（标题分配）
            ├── SKUGenerationClaim（SKU 领取协调）
            ├── LifecycleEvent（审计事件）
            └── ProductionPauseControl（生产暂停控制）
```

### 1.3 核心状态机

**商品（Product/Revision）状态**：
```
DRAFT → FROZEN → READY_FOR_PUBLISH
```

**图片任务（ImageJob）状态**：
```
PENDING → PLANNED → CLAIMED → CALLING → ASSET_RECORDED → SETTLED
```

**标题（TitleReservation）状态**：
```
AVAILABLE → RESERVED → USED
```

**生产保护（ProductionPauseControl）状态**：
```
PAUSED → TRIAL_RUNNING → (全部通过) → RESOLVED
                ↓ (任一失败)
             PAUSED（重新暂停）
```

## 二、详细功能说明

### 2.1 批次创建流程

**入口**：`POST /batches` → `WebRuntime.create_batch()` → `BatchService.create()`

**执行步骤**：
1. 验证产品类型已启用且有已安装的生产配置
2. 验证使用场景、风格、配色有效
3. 生成规范 JSON 请求快照，写入 `artifacts/requests/frontend/<hash>.json`
4. 调用 `CreateBatchCommand.execute()`：
   a. 验证请求快照哈希一致
   b. 在**同一数据库事务**内：
      - 分配 N 个 SKU（前缀 + 定宽流水号）
      - 创建 N 个 Product + ProductRevision + ListingConcept
      - 创建 Batch 记录
   c. 提交事务
5. 触发批次生产准备（`prepare_batch`）

**关键类**：
- `CreateBatchCommand` — 不可变命令对象，含幂等键
- `ProductDraft` — 产品概念草稿（Profile/Policy/Object/UseCase 等固定 pin）
- `BatchService` — 编排服务

---

### 2.2 批次生产准备（Batch Preparation）

**入口**：`POST /batches/{id}/prepare` → `BatchProductionPreparationService.prepare_batch()`

**执行步骤**（对每个 SKU）：
1. **标题分配**（F3）：从预审批标题池找到兼容标题 → RESERVED
2. **Primary 语义解析**：从绑定的 Title → Primary Query → 提取结构化语义
3. **对象解析**：按优先级规则解析载体对象（GIFT_BOX 等）
4. **概念冻结**：将对象 + 表面 + 艺术品事实写入 ListingConcept，计算 core_hash
5. **渲染提示词**：8 个槽位各生成一个完整 Prompt
6. **创建图片任务**：8 个 ImageJob 记录
7. **发布冻结计划**：写入 `codex-image-task-v1` JSON 文件

**关键文件**：
- 冻结计划：`<plans_dir>/<workspace_id>/<revision_id>.json`
- 计划格式：`{package: {...}, sha256: "..."}`

---

### 2.3 图片生成 — Codex 路线

**协议**：本地 Runner HTTP（`127.0.0.1:<port>`）

**通信流程**：
```
Codex 执行器                    CustomFactory
    │                               │
    │── POST /runner/claim ────────→│ 领取 SKU 任务
    │←── {package, jobs...} ───────│
    │                               │
    │── POST /runner/start ────────→│ 开始某张图
    │←── {prompt, params, ref...} ─│（含 Slot01 参考图路径）
    │                               │
    │  [调用图片生成 API]            │
    │                               │
    │── POST /runner/upload ───────→│ 上传 PNG（base64）
    │←── {ASSET_VERIFIED, ...} ────│ SHA-256 校验 + 存储注册
    │                               │
    │── POST /runner/finish ───────→│ 完成 SKU
    │←── {status: "COMPLETED"} ────│
```

**安全措施**：
- 仅 127.0.0.1 回环地址
- Bearer Token（≥32 字符，环境变量传入）
- 每个 Token 绑定 workspace + executor 身份
- 上传字节 SHA-256 必须与本地文件一致
- Slot01 为后续图片提供参考图（需通过技术验证）

**关键类**：
- `CodexSkuRunnerAPI` — 服务端 API（claim/start/fail/finish/upload/verify-result）
- `CodexSkuRunnerClient` — 客户端（含原始文件收据管理）
- `SkuGenerationClaimService` — SKU 领取协调（幂等 + 排他锁）
- `UnifiedImageIngestService` — 统一图片接收（API/Codex 共用）

---

### 2.4 图片生成 — API 路线

**配置**：
```python
OpenAICompatibleImageConfig(
    config_name="...",
    base_url="https://api.xxx.com/v1",
    api_key="sk-...",
    model="gpt-image-1",
    api_type="openai_compatible"
)
```

**协议**：`POST {base_url}/images/generations`

**请求参数白名单**：`size`, `quality`, `style`, `background`, `output_format`, `response_format`, `n`

**安全措施**：
- API Key 仅在内存中，不持久化
- 30 秒超时，不自动重试
- 禁止重定向，禁止代理
- 拒绝 localhost/private IP 的图片下载 URL
- 响应体上限 20MB
- 结果以 base64 或 HTTPS URL 返回

**当前状态**：代码完整实现，但 UI 中禁用（`route != 'CODEX'` 抛 `WEB_API_DISABLED`）

### 2.5 图片质检详细规则

#### 2.5.1 技术质检（Technical QA）

**检查项**：
| 检查 | 失败原因码 |
|------|-----------|
| 文件存在且可读 | `MISSING_FILE` |
| SHA-256 匹配 | `CHECKSUM_MISMATCH` |
| 字节数匹配 | `CORRUPT_ASSET` |
| PNG 完整解码 | `INVALID_PNG` |
| 完整性状态 VERIFIED | `INTEGRITY_FAILURE` |
| 尺寸 = 注册宽高 | `DIMENSION_MISMATCH` |
| 满足角色尺寸策略 | `DIMENSION_MISMATCH` |
| 无透明像素 | `TRANSPARENCY` |

**策略**：追加式记录，不可修改已有 ImageQA 行

#### 2.5.2 语义质检（Semantic QA）

**检查原因码**：
- `PRODUCT_MISMATCH` — 与产品概念不符
- `ROLE_MISMATCH` — 与图片角色不符
- `CONCEPT_INCONSISTENCY` — 概念不一致
- `TEXT_ERROR` — 文字错误
- `VISUAL_DEFECT` — 视觉缺陷
- `REVIEW_REQUIRED_UNCERTAIN` — 不确定，需人工

**当前状态**：无真实多模态提供者，`REVIEW_REQUIRED_UNCERTAIN` 存为 FAIL 需人工

#### 2.5.3 人工复审（Human Review）

**粒度**：按 SKU 集合（一次审核 8 张图）

**操作**：
- 完成本套审核（标记全部完成）
- 逐图标记"有问题"（需填写备注）
- 逐图"改为通过"
- 一键"全部通过"/"全部有问题"
- 查看审核历史（追加式记录）

**约束**：
- 硬技术失败不可人工 PASS
- 反转自动结果需选择原因码
- `OTHER` 原因需填写说明
- 并发保护：快照校验（stale snapshot 拒绝）

#### 2.5.4 OCR 文字质检

**运行时**：本地 PaddleOCR（`runtime/ocr/`）

**检测流程**：
1. 图片注册后自动触发 OCR 提取
2. 对照规则检测禁止文字
3. 结果存为 `OCR_QA` 记录
4. 需人工确认 PASS/FAIL

**禁止文字示例**：Water Resistant, UV Resistant, Scratch Resistant, Durable, Long Lasting, Waterproof, Dishwasher Safe 等

### 2.6 生产保护详细机制

**数据表**：`production_pause_controls`

**字段**：
- `scope_kind` — PRODUCT_TYPE_SCOPE / PROVIDER_MODEL_SCOPE / SYSTEM_SCOPE
- `target` — JSON（product_type_id / provider+model / 空）
- `state` — PAUSED / TRIAL_RUNNING / RESOLVED
- `trigger_rule_id` — 触发的规则 ID
- `trial_sku_limit` — 试运行 SKU 上限（默认 3）
- `trial_claim_count` / `trial_completed_count` / `trial_pass_count` / `trial_fail_count`

**调用时机**：
1. **领取时**：`SkuGenerationClaimService.claim()` 检查是否暂停
2. **QA 后**：配置的 QA 提交后在同一事务内触发 Guard 评估
3. **存储错误**：`UnifiedImageIngestService` 捕获 OSError 上报

**试运行恢复**：
```
人工点击"开始试运行" → TRIAL_RUNNING
  → 领取最多 3 个 SKU
  → 每个完成 QA 后检查
  → 3/3 全部 PASS → 自动解除暂停
  → 任一 FAIL → 重新 PAUSED
```

---

### 2.7 READY 判定详细流程

**入口**：`POST /skus/{id}/ready` → `ReadyService.mark_ready()`

**原子事务内检查**：
1. Product 有永久 SKU
2. ListingConcept 状态 = FROZEN
3. 标题身份匹配（TitleAsset 存在且已审批）
4. ProductData 存在且 QA 指纹匹配
5. 冻结图片清单存在且哈希匹配
6. 图片数 ≥ min_ready_count
7. 所有必需角色都有通过的图片
8. 每张选中图片：
   a. 实际字节完整性 VERIFIED
   b. 当前有效 QA = PASS
9. 首次 READY：原子创建 TitleUsage + TitleReservation 状态变更 + Revision 状态 + 审计事件

**READY 后**：状态 `READY_FOR_PUBLISH`，后续修订不再消耗新 Title

---

### 2.8 TEMU 模板导入与预览

**导入流程**：
```
Excel 文件 → parse_excel() → 验证 37 列 → 分类字段
  → 验证 12 变体（4 尺寸 × 3 数量）
  → 内容哈希去重 → 版本快照存储
```

**预览流程**：
```
READY Revision → 读取冻结 ProductData + 图片清单
  → 填充动态字段（标题/SKU/图片引用）
  → 展开 12 行变体
  → 检查价格配置 → 输出 publish_ready 状态
```

**存储**：`artifacts/test/dianxiaomi_publishing_profiles_v1/<workspace_id>/`
- `templates/<template_id>/<version>.json` — 模板快照
- `profiles/<profile_id>.json` — 发布配置

### 2.9 Web 前端安全模型

| 措施 | 实现 |
|------|------|
| 仅本机访问 | 中间件检查 `request.client.host ∈ {127.0.0.1, ::1}` |
| CSRF | Session 中随机 token，表单校验 |
| Origin 校验 | POST 必须来自同源 |
| CSP | `default-src 'self'` |
| 禁止嵌入 | `X-Frame-Options: DENY` |
| Session | HttpOnly + SameSite=Strict + 8h 过期 |
| 无缓存 | `Cache-Control: no-store` |
| 表单限制 | 32KB 上限，最多 20 字段 |
| 主机白名单 | `TrustedHostMiddleware` |

## 三、页面功能清单

### 3.1 生产总览（`/`）

**指标面板**：
- 等待生产 / 正在生图 / 等待QA / 待人工复审 / 内容生产完成 / 失败

**内容**：
- QA 规则待复盘提醒（当达到校准门槛时）
- 最近批次列表（点击进入批次详情）
- 执行会话列表（活跃 Codex Claim）

### 3.2 创建批次（`/batches/new`）

**表单字段**：
- 产品类型（下拉或只读）
- 使用场景（下拉或只读）
- 生产数量（数字输入，≥1）
- 图片生成方式（Codex 选中，API 禁用）
- 视觉偏好（折叠面板）：
  - 视觉风格：系统自动 / 现代高级 / 电商清晰 / 小商家可爱 / 极简北欧
  - 配色：系统自动 / 奶油中性色 / 鼠尾草绿 / 青绿色 / 黑白灰

### 3.3 SKU 详情（`/skus/{id}`）

**内容**：
- 头部：SKU、标题、版本、阶段、图片进度
- READY 区块：内容状态 + 阻塞原因 + READY 按钮
- 图片网格：8 张卡片，每张显示
  - 槽位号 + 角色名
  - 自动审核结果
  - 人工审核结果
  - 失败原因
  - 单图人工复审表单
- 最终有效图片清单
- 冻结的最终清单（READY 后显示）
- 高级诊断（折叠）：Policy ID/版本/哈希、每个 Job/Attempt/Asset 详情

### 3.4 操作员复审（`/reviews/skus/{id}`）

**布局**：
- 头部：SKU、品牌、对象、状态、导航（上一个/下一个）
- 批次进度条：已审核 X/Y、全通过/含问题/全问题计数
- 筛选："只看有问题"
- 图片网格（4 列）：
  - 技术 ✓/✕/待检查
  - 人工 ✓/✕/—
  - OCR 区域标记（SVG 叠加）
  - 问题备注
  - 逐图操作：标记有问题 / 改为通过
  - 审核历史（折叠）
- 底部操作：
  - 完成本套审核（主按钮）
  - 确认全部 8 张通过（折叠在"更多操作"）
  - 全部 8 张有问题（折叠，需备注）
- 灯箱：点击图片放大，支持左右箭头切换

### 3.5 QA 校准（`/calibration`）

**每个产品类型显示**：
- 人工复审图片数
- 机器与人工一致率
- 漏检数（FALSE_PASS）
- 误杀数（FALSE_FAIL）
- 按图片角色分歧表
- 按原因分歧表
- QA 规则待复盘提醒

### 3.6 生产保护（`/guard`）

**每个暂停控制显示**：
- 范围 + 状态
- 受影响目标
- 触发规则 ID + 规则文本
- 暂停原因
- 暂停/更新时间
- 试运行按钮（PAUSED 时）或进度（TRIAL_RUNNING 时）

**规则表**：展示当前版本的所有规则
